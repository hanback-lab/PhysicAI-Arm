# Preparation

이번 장에서는 토큰 색상에 따라 분류 동작을 수행하는 policy를 학습합니다. 목표 작업은 **빨간 토큰은 왼쪽 박스에 넣고, 초록 토큰은 오른쪽 박스에 넣기**입니다. Chapter 8과 같은 방식으로 ROS 2에서 원시 데이터를 수집하고, LeRobot 학습 데이터셋으로 변환한 뒤, 학습된 policy를 실제 로봇 제어에 연결합니다.

실습에는 총 3개의 노드가 필요합니다.

- `classification_logger_node.py`: 에피소드별 원시 데이터 저장
- `classification_parsing_node.py`: 원시 데이터를 LeRobot 데이터셋으로 변환
- `classification_inference_node.py`: 학습된 policy를 이용한 실시간 추론 및 제어

학습은 별도 ROS 2 노드가 아니라 LeRobot의 `lerobot-train` 명령으로 진행합니다. 모든 실습은 workspace(`/home/soda/physicai_arm_ws`)에서 진행합니다. 다른 경로에서 진행할 경우, 코드마다 경로를 변경해야 합니다.

세 노드의 전체 코드와 상세 설명은 [8-1. Preparation](/Chapter08.%20Pick%20the%20Red%20Token/8-1.%20Preparation.md)과 동일합니다. 해당 코드를 `classification_*` 이름으로 복사한 뒤, 이 장에서 안내하는 값(저장 폴더, task 이름, 데이터셋 저장소, 정책 경로)만 바꿔 사용합니다.

## logger_node

이 노드는 학습에 필요한 데이터를 에피소드 단위로 저장합니다. 첫 에피소드는 노드 실행과 동시에 자동으로 기록됩니다. 기록을 마친 뒤 성공이면 `s`, 실패면 `f`를 입력합니다. 다음 에피소드는 `start`를 입력해 시작하고, `q`를 입력하면 종료합니다.

이번 장에서는 저장 폴더(`save_dir`)를 `dataset_raw_classify`, task name(`task_name`)을 `classify_tokens`로 사용합니다. `classification_parsing_node`의 `RAW_ROOT`도 `./dataset_raw_classify`, `TASK_DEFAULT`도 `classify_tokens`로 맞춥니다. `parsing_node`는 metadata.json의 `task_name`이 `classify`이면 `TASK_DEFAULT` 값으로 바꿔 저장하므로, task name에는 `classify`가 아닌 `classify_tokens`를 사용합니다.

이번 작업에서는 토큰 색상에 따라 목적지가 달라지므로, 데이터 수집 시 빨간 토큰은 항상 왼쪽 박스에, 초록 토큰은 항상 오른쪽 박스에 넣어야 합니다. 색상과 목적지가 섞이면 policy가 잘못된 행동을 학습할 수 있습니다.

## parsing_node

`classification_parsing_node`는 `classification_logger_node`가 저장한 원시 데이터를 LeRobot이 학습할 수 있는 데이터셋 형식으로 변환합니다. 실패한 에피소드는 제외하고, timestamp 기준으로 이미지, state, action을 정렬한 뒤 학습 입력 크기에 맞게 resize합니다. `TOP_CALIB_PATH`/`FRONT_CALIB_PATH`에 지정한 캘리브레이션 YAML 파일로 이미지 왜곡 보정도 함께 적용합니다. 지정한 파일이 없으면 오류로 종료되므로, 캘리브레이션을 사용하지 않는다면 두 값을 `None`으로 바꿉니다. 또한 top 이미지는 Chapter 8과 동일하게 `TOP_MASK` 영역을 회색으로 가립니다.

변환이 끝나면 `dataset.push_to_hub()`로 `OUT_REPO_ID`에 지정한 Hugging Face 저장소에 데이터셋을 업로드합니다. 실행 전 터미널에서 `huggingface-cli login`으로 쓰기 권한이 있는 토큰을 등록하고, `OUT_REPO_ID`의 `<id>/<dataset_name>`을 본인 Hugging Face 사용자명과 이 장의 데이터셋 이름(`classify_tokens_dataset`)으로 바꿔야 합니다.

## inference_node

`classification_inference_node`는 학습된 policy를 실제 로봇의 센서 입력과 joint target 출력으로 연결하는 노드입니다. 현재 카메라 이미지와 joint 상태를 입력받아 다음 action을 예측하고, 이를 `/follower/joint_targets`로 publish합니다.

학습된 policy는 카메라 이미지에서 토큰 색상과 위치, 박스 위치를 함께 보고 행동을 예측합니다. 따라서 추론 시에도 학습할 때와 동일하게 top/front 이미지와 joint state를 입력해야 합니다. 파싱 단계에서 캘리브레이션을 적용했다면, 추론 노드의 `top_calib_path`/`front_calib_path`에도 **같은 YAML 파일**을 지정해야 학습과 추론의 입력이 어긋나지 않습니다. 추론 노드는 파일을 찾지 못하면 경고만 출력하고 보정 없이 동작하므로 실행 로그를 꼭 확인합니다.

